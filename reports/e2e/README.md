## Where new results go

- When `MONGODB_CONNECTION_STRING` is configured, the common runner stores run documents in `guarded_autonomy.guarded-autonomy-layers-e2e-runs` and recorded HTTP events in `guarded_autonomy.guarded-autonomy-layers-e2e-evidence`. A run document's `_id` is `<run_id>/<invocation_id>`; evidence documents carry the same run and invocation IDs plus case ID and event index. Database and collection prefix are configurable. No local report/evidence files are generated in this mode.
- Without MongoDB configuration, the common runner writes each invocation to `comprehensive/<run_id>/<invocation_id>/` for full core runs, or `narrow/<run_id>/<invocation_id>/` for selected groups and smoke. Setup snapshots and manifests remain in `setup/<run_id>/` in both modes; private credentials and resume state remain in ignored `.e2e/`.
- The interactive comprehensive API session writes its journal under `reports/e2e/comprehensive/<run_id>/`.
- Focused semantic and background E2E scripts write under `reports/e2e/narrow/` by default. Pass `--output` to choose another explicit path.
- Infrastructure probes belong under `reports/e2e/infrastructure/` when saving their output.

Keep each run's original report and timestamp. Add a row here describing its scope and result; do not merge separate runs into a synthetic overall pass rate. Reports may contain request text and database identifiers, so review contents before publishing them outside the project.
